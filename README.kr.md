# AI Label Filter for YouTube

YouTube가 직접 "AI로 제작됨" 라벨을 붙인 영상을 숨기고, 영상마다 왜 숨겼는지 알려 주는 크롬 익스텐션입니다.
추측하지 않고, 서버도 계정도 없습니다.

## 기능

- **YouTube 자체 라벨 사용** — YouTube가 제목 아래에 AI 배지를 표시한 영상만 AI로 판정합니다
- **시청 페이지 배너** — 연 영상에 라벨이 있으면 **Hide this channel**(이 채널 숨기기) / **Dismiss**(닫기) 배너를 띄웁니다
- **피드 필터링** — 홈·검색·사이드바에서 라벨이 확인된 영상, 직접 차단한 채널, 자동으로 표시된 채널, (켰다면) AiSList에 등록된 채널의 카드를 숨깁니다 <!-- TODO verify: 대상 화면 목록 (구독, 채널 페이지, Shorts 선반) -->
- **숨기기 또는 흐리게** — 카드를 숨기거나(기본값), 흐리게 표시하고 이유 칩을 붙입니다
- **그래도 보기** — 카드 하나를 클릭 한 번으로 다시 보이게 합니다 <!-- TODO verify: 숨기기 모드에서 "그래도 보기"에 접근하는 방법 -->
- **허용 목록** — 신뢰하는 채널은 어떤 이유로도 숨기지 않습니다
- **팝업** — 전체 켜기/끄기, 이유별 숨긴 개수, 차단 목록과 허용 목록
- **오류 시 보여주기** — 문제가 생기면 영상을 숨기지 않고 보여줍니다

## 판정 방식

### 신호

YouTube는 AI로 제작됐다고 라벨을 붙인 영상의 제목 아래에 작은 "AI" 배지를 표시합니다. 이 배지는 YouTube 웹 앱이 시청 페이지를 불러올 때 받는 데이터에는 들어 있지만, 홈·검색·사이드바 카드 데이터에는 없습니다. 그래서 피드에 있는 영상에 라벨이 붙어 있는지 알려면 그 영상에 대해 YouTube에 물어보는 수밖에 없습니다.

이 확장은 영상당 작은 요청 1건을 `/youtubei/v1/next`로 보냅니다. YouTube 웹 앱이 시청 페이지를 불러올 때 쓰는 바로 그 엔드포인트입니다. 이 요청은

- 백그라운드가 아니라 YouTube 페이지 자체(`www.youtube.com`)에서 보내고
- 쿠키를 빼고 보내므로 YouTube·Google 계정과 연결되지 않으며
- 필요한 필드 몇 개(제목 아래 배지, 영상의 채널)만 요청하므로 응답이 수백 KB가 아니라 약 1 KB입니다

응답에 YouTube의 AI 배지(내부적으로 스타일 `BADGE_STYLE_TYPE_SIMPLE`, 아이콘 `INFO`인 `metadataBadgeRenderer`)가 있을 때**만** AI 영상으로 판정합니다. "제작 방식(How this was made)" 패널만 있는 경우는 판정에 쓰지 **않습니다**. 자동 더빙 영상이나 "카메라로 촬영됨" 표시가 있는 영상에도 이 패널이 나오기 때문입니다.

### 어디서 확인하나

| 위치 | 요청 | 동작 |
|---|---|---|
| 시청 페이지 | 연 영상 1건 | 라벨이 있으면 **Hide this channel**(이 채널 숨기기) / **Dismiss**(닫기) 배너를 띄웁니다. 결과는 캐시합니다. |
| 피드 (기본) | 없음 | 기기에 이미 저장된 정보로만 카드를 숨깁니다 (아래 참고). |
| **Check videos in feeds**(피드 영상 확인)을 켠 피드 (기본 꺼짐) | 캐시된 결과가 없는 보이는 영상마다 1건, 한 번에 하나씩, 최소 1초 간격 | 라벨이 확인되는 대로 숨깁니다. |

### 카드를 숨기는 이유

아래 순서로 판단합니다.

1. **허용 목록** — 허용 목록에 있는 채널이면 항상 보여줍니다.
2. **차단한 채널** — 배너나 팝업에서 직접 차단한 채널입니다.
3. **AI 제작 라벨** — 영상 자체에 라벨이 확인됐습니다.
4. **자동 표시된 채널** — 이 기기에서 같은 채널의 라벨 붙은 영상을 2개 이상 확인했습니다.
5. **AiSList에 등록됨** — AiSList를 켠 경우에만 해당합니다.

어디에도 해당하지 않으면 보여줍니다.

결과는 기기에 캐시합니다. 라벨이 없던 영상은 30일(YouTube가 나중에 라벨을 붙일 수 있으므로), 라벨이 있는 영상은 180일입니다.

### 문제가 생겼을 때

- **오류** (네트워크 실패, 예상과 다른 응답, 삭제된 영상) — 영상을 보여주고 캐시하지 않습니다.
- **YouTube가 거부할 때** (HTTP 403·429, 또는 "비정상적인 트래픽"/"Sorry" 페이지) — 모든 요청을 24시간 동안 멈춥니다.
- **하루 1회 자가 진단** — 라벨이 붙어 있는 것으로 알려진 영상 몇 개를 하루에 한 번 확인합니다. 라벨을 찾지 못하면(예: YouTube가 데이터 형식을 바꾼 경우) 팝업에 탐지가 고장났을 수 있다는 경고를 띄웁니다. <!-- TODO verify: 전체 꺼짐 상태나 요청 정지 중에도 자가 진단이 도는지 -->

## 개인정보

서버가 없습니다. 개발자에게는 아무것도 전송되지 않습니다. 이 확장이 보내는 요청은 아래가 전부입니다.

| 언제 | 요청 | 받는 곳 | 내용 | 쿠키 |
|---|---|---|---|---|
| 시청 페이지를 열 때 | `POST /youtubei/v1/next` 1건 (필드 마스크) | `www.youtube.com` | 그 영상의 ID와 YouTube 웹 클라이언트 기본 필드 <!-- TODO verify: 정확한 요청 본문 (client name/version, hl/gl?) --> | 보내지 않음 |
| **Check videos in feeds**(피드 영상 확인)을 켰을 때 | 같은 요청, 캐시된 결과가 없는 보이는 영상마다, 초당 최대 1건 | `www.youtube.com` | 그 영상의 ID | 보내지 않음 |
| 하루 1회 (자가 진단) | 같은 요청, 기준 영상 몇 개 | `www.youtube.com` | 기준 영상의 ID | 보내지 않음 |
| AiSList를 켰을 때, 24시간에 최대 1회 | [AiSList 차단 목록 파일](https://github.com/Override92/AiSList) `GET` | `raw.githubusercontent.com` | 일반 파일 다운로드, 사용자 정보 없음 | 해당 없음 |

여느 웹 요청과 마찬가지로 YouTube와 GitHub는 IP 주소와 브라우저 user agent를 봅니다. YouTube는 자기가 보여준 영상이 무엇인지 이미 알고 있고, 이 요청은 바로 그 영상들에 대해서만 묻습니다.

`chrome.storage`에만 저장하고 다른 곳에는 저장하지 않습니다: 설정, 차단 목록과 허용 목록, 영상별 결과 캐시, 채널별 라벨 영상 개수, 내려받은 AiSList 사본, 팝업에 표시하는 숨긴 개수. <!-- TODO verify: storage.local만 쓰는지, 설정은 storage.sync인지 --> 확장을 삭제하면 모두 지워집니다.

분석 도구, 원격 측정, YouTube Data API, 계정 모두 없습니다. 자세한 내용은 [PRIVACY.md](PRIVACY.md)를 참고하세요.

| 권한 | 필요한 이유 |
|---|---|
| `storage` | 설정, 차단 목록, 허용 목록, 결과 캐시, AiSList 사본을 기기에 저장합니다. |
| `*://www.youtube.com/*` 콘텐츠 스크립트 | YouTube 페이지의 영상·채널 링크를 읽고, 카드를 숨기거나 흐리게 하고, 시청 페이지 배너를 띄우고, 라벨 요청을 YouTube 페이지 자체에서 보냅니다. 요청이 `www.youtube.com`에서 나가므로 별도 호스트 권한이 필요 없습니다. |
| 선택: `https://raw.githubusercontent.com/*` | AiSList를 켜는 순간에만 요청하고, 그 목록을 내려받는 데만 씁니다. AiSList를 켜지 않으면 이 권한을 요청하지 않습니다. <!-- TODO verify: AiSList를 끄면 권한도 반납하는지 --> |

`tabs`, `history`, "모든 웹사이트의 데이터 읽기 및 변경" 같은 권한은 요청하지 않습니다.

## 자주 묻는 질문

**왜 머신러닝이나 휴리스틱으로 AI 영상을 탐지하지 않나요?**
제목·썸네일·음성으로 추측하면 오탐이 생기고, 영상이 왜 사라졌는지 알 수 없게 됩니다. 이 확장은 책임 주체가 있는 신호만 씁니다. YouTube의 라벨, 사용자 본인의 차단 목록, 그리고 (켰다면) 사람이 검토하는 커뮤니티 목록입니다. 숨긴 카드에는 모두 확인하고 되돌릴 수 있는 이유가 있습니다.

**왜 YouTube와 통신해야 하나요?**
YouTube는 홈·검색·사이드바 카드 데이터에 AI 라벨을 넣지 않습니다. 라벨은 영상 시청 페이지 데이터에만 있습니다. 그래서 영상에 라벨이 있는지 알려면 그 영상에 대해 YouTube에 물어봐야 합니다. 이 확장은 YouTube 페이지에서 YouTube에 직접, 쿠키 없이, 필요한 필드 몇 개만 묻습니다. (확장의 백그라운드 서비스 워커에서 보내면 YouTube가 이 요청을 거부한다는 점도 페이지에서 보내는 이유입니다.)

**YouTube가 느려지나요?**
기본 상태에서는 시청 페이지마다 응답 약 1 KB짜리 요청 1건이 추가될 뿐입니다. 피드 필터링은 기본적으로 네트워크 요청 없이 기기 안에서만 조회합니다. **Check videos in feeds**(피드 영상 확인)을 켜면 보이는 카드에 대해서만, 한 번에 하나씩, 최소 1초 간격으로 요청하고, 결과는 캐시합니다 (30일 / 180일).

**YouTube가 요청을 제한하거나 차단할 수 있나요?**
이 엔드포인트는 공개 문서가 있는 API가 아니라 YouTube 내부 API라서 보장은 없습니다. YouTube는 언제든 제한하거나 바꿀 수 있습니다. 이 확장은 요청 빈도를 낮게 유지하고(위 참고), 쿠키를 빼서 계정과 연결되지 않게 하며, YouTube가 403·429나 "Sorry" 페이지로 응답하면 모든 요청을 24시간 멈춥니다. 다만 요청은 여전히 사용자의 IP 주소에서 나갑니다. 피드에서 추가 요청을 전혀 원하지 않으면 **Check videos in feeds**(피드 영상 확인)을 꺼 두세요 (기본값).

**누가 봐도 AI 영상인데 그대로 보여요.**
YouTube 라벨이 없는 영상일 가능성이 큽니다. 맨 위의 한계를 참고하세요. 팝업에서 채널을 차단하거나, AiSList를 켜서 더 넓게 걸러낼 수 있습니다.

**AiSList가 AI 채널이 아닌 채널을 숨겼어요.**
그 채널을 허용 목록에 추가하면 다시는 숨겨지지 않습니다. 모두를 위해 목록을 고치려면 [AiSList의 삭제 요청 절차](https://github.com/Override92/AiSList)를 이용해 주세요. 이 확장은 목록을 수정하지 않습니다.

**Shorts를 자동으로 넘기나요?**
아니요. v1에는 Shorts 자동 넘기기가 없습니다. <!-- TODO verify: 피드의 Shorts 카드도 일반 카드처럼 걸러지는지 -->

**YouTube가 데이터 형식을 바꾸면요?**
라벨 붙은 영상이 더 이상 탐지되지 않고 그대로 보입니다 (오류 시 보여주기). 하루 1회 자가 진단이 이를 감지해 팝업에 경고를 띄웁니다.
